# ToonLivre Source & Tests

This directory contains the ToonLivre extension source written in Rust and compiled to WebAssembly (WASM).

## WASM Integration Tests

ToonLivre uses dynamic cryptographic signatures generated by a Token Server to validate API requests. To run real integration tests on the WASM-compiled source, requests must be executed with the Token Server pointing to the local environment.

### 1. Token Server Host Resolution

By default, the ToonLivre source consumes the production Token Server (`https://toons.4nd.xyz`). However, during local integration test execution, requests must go to `http://localhost:3000`.

**Implemented solution:**

The `dev-server` feature in `Cargo.toml` allows overriding the Token Server host at compile time. The code in `src/token_server.rs` applies the override in the `token_server_url()` function:

```rust
pub fn token_server_url(endpoint: &str) -> Option<String> {
    let config = load_token_server_config()?;
    
    // Override host for dev-server feature
    #[cfg(feature = "dev-server")]
    let host = String::from("http://localhost:3000");
    #[cfg(not(feature = "dev-server"))]
    let host = config.host;
    
    let base = host.trim_end_matches('/');
    let path = endpoint.trim_start_matches('/');
    Some(format!("{}/{}", base, path))
}
```

This approach keeps the configuration file `res/token-server.json` unchanged (always pointing to production) and applies the override only when needed during tests.

### 2. Running Integration Tests

The `#[aidoku_test(live:test)]` macro marks tests that require active network connection. The `aidoku-test` runner (WASM environment) uses `reqwest::blocking` internally, allowing real HTTP requests from the test sandbox environment.

To run tests connecting to the local Token Server instance, execute the integration script:

```bash
./integration-test.sh
```

This script automates the following flow:

1. Checks if the Token Server is already running at `http://localhost:3000`
2. If not, starts the server in background: `bun run src/server.ts`
3. Waits until the `/health` endpoint returns status `200 ok`
4. Runs tests in WASM environment with the `dev-server` feature:
   ```bash
   cargo test --lib --features dev-server
   ```
5. Finishes execution and shuts down the Token Server cleanly (only if the script started it)

**Available tests:**

- `live_token_server_health` - Verifies Token Server health
- `live_fetch_releases` - Tests release listing
- `live_search_mangas` - Tests manga search
- `live_fetch_manga_by_slug` - Tests search by slug
- `live_fetch_manga_by_id` - Tests search by ID
- `live_fetch_manga_reader` - Tests reader endpoint
- `live_fetch_chapter_with_decryption` - Tests chapter decryption

### 3. API Format Corrections

The ToonLivre API underwent structural changes that were corrected:

**Multi-value Fields:**

Previously, `authors`, `artists` and `genres` fields returned as comma-separated strings (e.g., `"Author 1, Author 2"`). Now they are returned as arrays/lists (e.g., `["Author 1", "Author 2"]`).

Deserialization structs were updated:

```rust
#[derive(Debug, Clone, Deserialize)]
pub(crate) struct ApiMangaById {
    pub id: String,
    // ...
    #[serde(default)]
    pub authors: Vec<String>,  // Previously: Option<String>
    #[serde(default)]
    pub artists: Vec<String>,  // Previously: Option<String>
    #[serde(default)]
    pub genres: Vec<String>,   // Previously: Option<String>
    // ...
}
```

**Decrypted Chapter Payload:**

The payload returned when requesting the chapters endpoint is no longer a raw encrypted string, but a JSON object with a dynamic key containing the base64 encrypted value.

Example API response:
```json
{
  "148c43accc00672d": "U2FsdGVkX1+6T8sWKnd15aqajgs8W5b4ZrsdMq48efz+nt0K1aJ6..."
}
```

The request method was corrected to extract the first value from this container before passing it to the Rabbit algorithm decryption:

```rust
let body = if url.contains("/chapters/") {
    let obj: serde_json::Map<String, serde_json::Value> = 
        serde_json::from_str(&body)?;
    let encrypted_str = obj.values().next()?.as_str()?;
    decrypt_cryptojs_rabbit(encrypted_str, &passphrase)?
} else {
    body
};
```

### 4. Why Use Feature Instead of Environment Variable?

In the `aidoku-test` WASM environment, there is no access to `std::env` to read environment variables at runtime. The solution with compile-time features (`#[cfg(feature = "dev-server")]`) allows configuring behavior at compile time, which is the only option available in the no_std WASM context.
